# Security Policy

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting for the repository. Do not
open a public issue containing credentials, private repository names, customer
data, exploit details, or other sensitive information.

Include the affected version, reproduction steps, impact, and any proposed
mitigation. Maintainers will acknowledge the report and coordinate disclosure
after a fix is available.

## Supported versions

Security fixes target the latest released version. Development snapshots are
provided without a compatibility or security-support guarantee.

## Scope

Reports about path traversal, unsafe worktree cleanup, command injection,
credential exposure, or unintended data sent to an AI provider are especially
welcome.
