# 需求 — 01.demo-feature

> 演示用例：给后端服务添加 /api/health 健康检查接口。

## 目标

- 要解决的问题：线上没有轻量的健康检查接口，每次发版都要靠日志判断进程是否真的启动成功。
- 期望业务结果：负载均衡器和内部监控可以直接探活，并看到依赖的连通状态。

## 范围

- 包含：`GET /api/health` 与 `GET /api/health?detail=true`，暴露在 `/api/` 前缀下且无需鉴权。
- 不包含：监控告警系统接入；健康指标历史持久化。

## 约束

- 兼容性：与现有 Spring Actuator 不冲突（如果有）。
- 安全与权限：只返回连通状态，不暴露连接串或凭证。
- 数据与迁移：不依赖任何新组件，只查现有 DataSource / RedisTemplate / KafkaTemplate。

## 验收标准

| AC-ID | Given | When | Then | 优先级 |
|---|---|---|---|---|
| AC-001 | 服务已就绪 | 调用 `GET /api/health` | 200ms 内返回 200 与 `{"status":"ok"}` | P0 |
| AC-002 | 任一依赖不可用 | 调用 `GET /api/health?detail=true` | 返回各依赖状态并明确指出失败项，接口本身不崩溃 | P0 |
| AC-003 | 服务启动中、依赖未就绪 | 调用 `GET /api/health` | 返回 503，就绪后改为 200 | P1 |
